# x402 — machine payments sobre HTTP 402

[[estudos/agentic-commerce/index|← Agentic Commerce]]

> [!info] Camada 4 — settlement
> Standard de pagamento máquina-a-máquina da Coinbase, agora na Linux Foundation. Spec v2, adoption economicamente fina.
> Estado em **2026-09-29**. Para o mapa completo dos protocolos e as decisões de
> negócio, ver [[estudos/agentic-commerce/index|Agentic Commerce]].

### x402 (Coinbase → Linux Foundation)

- Spec v2 (2025-12-09): <https://github.com/x402-foundation/x402/blob/main/specs/x402-specification-v2.md>
- Docs: <https://docs.x402.org/> · **LF Foundation operacional em 2026-07-14**,
  40 membros.

**Premier Members**: Adyen, AWS, Amex, Circle, Cloudflare, Coinbase, Fiserv,
**Google, Mastercard, MoonPay, Ripple, Shopify, Solana Foundation, Stellar,
Stripe, Visa.**

Headers (v2, todos base64 JSON): `PAYMENT-REQUIRED` (S→C, com HTTP 402),
`PAYMENT-SIGNATURE` (C→S), `PAYMENT-RESPONSE` (S→C), `EXTENSION-RESPONSES`.

**Fluxo do facilitator** (dois endpoints, não três — não existe `/bind`):
```
C→S  GET /resource
S→C  402 + PAYMENT-REQUIRED
C    escolhe accepts[], monta PaymentPayload, assina
C→S  GET /resource + PAYMENT-SIGNATURE
S→F  POST /verify      (READ-ONLY — MUST NOT commitar estado onchain)
F→S  VerificationResponse
S    executa o trabalho
S→F  POST /settle      (commita estado)
F    broadcast + espera confirmação
F→S  SettlementResponse
S→C  200 + PAYMENT-RESPONSE
```

**Três fluxos de pagamento** (`extra.paymentFlow`): `authorization` (default,
verify → resource → settle), `upfront` (settle → resource, sem verify),
`escrow` (settle → resource → settle). O `upfront` é a resposta direta ao
problema de "free shopping".

Schemes: `exact` (irreversível, sem refund), `upto`, `batch-settlement`, e
**`auth-capture`** (o mais interessante: lifecycle `authorize`/`charge`/
`capture`/`void`/`refund`/`reclaim`; resposta ao fato de `exact` não ter
refund).

Redes: Base, Base Sepolia, Solana, devnet. Assets: EIP-3009 ERC-20s, SPL.
**Sem off-ramp fiat nativo.**

Extensions: `bazaar` (discovery), `builder_code`, `sign-in-with-x`,
`payment_identifier` (idempotência), `http-message-signatures`,
`extension-offer-and-receipt`, entre outras.

Transportes: HTTP, **MCP** (payment required = tool result com `isError: true`
+ `structuredContent`; payload em `_meta["x402/payment"]`), **A2A** (task em
`state: "input-required"`).

Default do `x402Client`: **teto de \$1 USD por pagamento**. E o aviso
documental: *"Avoid relying only on model prompts for spend controls; keep the
policy check in code near the payment client."*

### ⚠️ A adoção de x402 é muito menor que o número bruto sugere

Este é o ponto mais contra-intuitivo de todo o estudo, e o mais importante
para não ser enganado numa conversa de negócio.

Medição peer-reviewed ([arXiv:2607.12575](https://arxiv.org/abs/2607.12575),
14 jul 2026, 280 dias 2025-09-17 → 2026-06-23):
- Base: **136.708.672** settlements, **\$44.121.383,81** bruto.
- Concentração: Gini **> 0,98** em payer/recipient/value. Maior facilitator:
  63,54% (Base) / 67,72% (Solana).
- Decomposição: **21,20% fictício** (self-payment ou loop fechado provado),
  **63,78% settlement interno** dentro de cluster linkado a funding, 15,02%
  não atribuído. O tier C1 sozinho tem **54,08% do valor**.
- Demanda genuína **limitada entre \$187.861,35** e **\$20.258.746,09** —
  **duas ordens de grandeza de intervalo**.
- O contador inteiro de 136,7M settlements é **reproduzível por ~\$355.583 em
  gas patrocinado**.
- Conclusão do paper: *"Settlement count is thus a **Goodhart metric**… measures
  manufacturability, not adoption."*

Outros números, e a divergência:
| Fonte | Figura |
|---|---|
| arXiv (peer-reviewed) | 136,7M settlements; demanda real entre \$188K e \$20,3M |
| Visa/Artemis (2026-07-14, dados 2026-04-21) | ~\$15,0M ajustado / 109,6M transações, excluindo wash/test |
| USENIX Sec 2026 | 15 facilitators, 60K+ sellers, 360K+ buyers, 119M transações |
| x402stats.io (metodologia publicada) | \$793K orgânico/mês; **receita mediana do vendedor \$0,01 em 30 dias**; 76% do volume em 10 wallets |
| Sites de comparação | "167M/\$28K dia", "165M/69k agents" — ⚠️ **inconsistentes entre si por ordens de grandeza, não citar** |

> [!important] Para a sua decisão de negócio
> x402 é **tecnicamente real** (LF, 40 membros, spec v2, 4 schemes, 3
> transports, 9 extensões) e **economicamente fino**. Se alguém apresentar
> "100M+ de transações agentic" como evidência de uma economia de agentes,
> está cometendo exatamente o erro de Goodhart que a literatura peer-reviewed
> já documentou.
